# 开发指南

本文面向修改源码、测试和发布便携包的维护者。普通用户从 [README](../README.md) 下载软件并按步骤操作即可。独立接入 Claude Code 插件见 [Claude Code 接入说明](../CLAUDE_CODE接入说明.md)。

## 源码运行

开发环境：Windows x64、Python 3.13、Node.js 22+；浏览器测试使用本机 Chrome。获取源码后，在仓库根目录打开 PowerShell，执行：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock
npm --prefix frontend ci
npm --prefix frontend run build
.venv\Scripts\python.exe launcher.py start
```

之后可双击源码目录的 `start.vbs` / `stop.vbs`，或使用以下命令停止服务：

> ⚠️ `start.vbs` 必须用 `python.exe`（隐藏窗口）而不是 `pythonw.exe` 启动：claude.exe 是控制台程序，在完全无控制台的进程链下启动会报 `0x0000142`（DLL 初始化失败）。隐藏的控制台不影响使用。勿改回。

```powershell
.venv\Scripts\python.exe launcher.py stop
```

`app.py` 是启动器的兼容入口。当前工作台使用 React 和 FastAPI。

开发前端时，在两个终端分别启动后端和 Vite：

```powershell
.venv\Scripts\python.exe server.py
```

```powershell
npm --prefix frontend run dev
```

打开 Vite 输出的地址；开发页通过本机代理访问 FastAPI。后端默认端口为 8000。直接启动 `server.py` 时可通过 `COMPLIANCE_PORT` 设置端口；调整端口后需同步修改 Vite 代理配置。`launcher.py` 优先使用 8000，冲突时自动选择空闲端口，重复启动会打开已运行的实例。

## 配置与数据

模型配置优先使用工作台界面。源码开发的环境变量示例见 [`.env.example`](../.env.example)；界面已保存的配置优先于 `.env` 和环境变量。`COMPLIANCE_DATA_DIR` 可指定独立测试目录，例如：

```powershell
$env:COMPLIANCE_DATA_DIR = Join-Path $PWD 'build\manual-test-data'
.venv\Scripts\python.exe launcher.py start
```

默认数据目录为 `%LOCALAPPDATA%\AIComplianceWorkbench`：

| 目录或文件 | 内容 |
| --- | --- |
| `settings.json` | 模型与可选 MCP 配置；密钥使用 Windows DPAPI 加密 |
| `reports/` | 结构化报告，包含正文及材料短预览 |
| `reviews/` | 与报告 ID 关联的逐项复核记录，JSONL 格式 |
| `logs/startup.log` | 启动失败的脱敏提示 |
| `instance.json` | 当前服务的进程及端口记录 |

DPAPI 密钥绑定当前 Windows 用户，换机或换用户后需重新填写。界面不读取密钥明文，不在浏览器持久化存储中保存密钥。修改设置对下一次审查生效；更换服务地址或鉴权方式需要重新填写模型密钥。

网络默认直连；需要 HTTP(S) 代理时在界面选择“使用系统代理”。连接测试与正式审查使用同一网络设置和审查引擎。模型 API Key 与兼容服务的 Bearer Token 二选一，也支持已有的本机 Claude 登录。

法规检索默认使用本地语料。在线 MCP 服务由界面启用、选择并填写地址及可选令牌；关闭在线检索会保留连接资料，但不加载连接。已有非空 MCP 地址配置会自动迁移为启用状态。模型连接测试不验证在线法规服务。

单实例同时审查一份材料。刷新可恢复当前服务实例中的任务与结果；停止服务后不恢复页面状态，已保存文件仍保留。预扫描风险与 Agent 报告分别展示；预扫描失败标记为“未完成”。所有命中项都需选择复核动作，L3/L4 和规则指定项目标为必须复核。复核不会修改原始报告，“退回重审”不会自动调用模型。

审查失败或取消不生成成功报告；报告磁盘保存失败时页面仍允许下载；复核写入失败可以重试。文件限制及用户操作详见 README。

## 测试

在仓库根目录运行后端与前端测试：

```powershell
.venv\Scripts\python.exe -m pip install pytest pytest-asyncio
.venv\Scripts\python.exe -m pytest tests -q
npm --prefix frontend test
npm --prefix frontend run test:e2e
```

浏览器测试使用本机 Chrome、独立测试服务器及模拟 Agent，不消耗模型额度。测试服务器使用 8011 端口；执行前确认该端口空闲。截图与测试产物位于 `output/playwright/`。

README 截图使用隔离数据目录和无密钥状态采集，模型设置图选择 DeepSeek，但不填写真实密钥或执行连接测试。先在 `output/playwright/` 检查截图，再将最终图片放入 `docs/images/`。更新界面按钮时同步核对使用说明和截图。

## 构建与发布

### 构建便携包

在已安装上述开发依赖的 Windows x64 环境、仓库根目录运行：

```powershell
.venv\Scripts\python.exe scripts\build_portable.py
.venv\Scripts\python.exe scripts\verify_portable.py
```

构建脚本重新构建前端，下载运行时并安装锁定依赖，输出到 `dist/`：

- `AI-Compliance-Workbench/`：可直接启动的解压目录。
- `AI-Compliance-Workbench-Windows-x64.zip`：向用户提供的便携包。
- `AI-Compliance-Workbench-Windows-x64.sha256`：该 ZIP 的 SHA256 校验值。

下载缓存在 `build/downloads/`。仅在前端产物已更新时使用 `--skip-frontend` 跳过前端构建；需要构建代理时可添加 `--proxy http://host:port`，代理仅用于本次构建。

便携包包含嵌入式 Python、锁定依赖、SDK 内置 CLI、PortableGit、本地插件语料、字体、前端资源和带截图的 README。开发指南通过 README 中的 GitHub 链接访问。第三方许可保留在依赖目录、字体目录和 `licenses/`。不将 Git 元数据、真实配置、用户材料或运行日志放入发布包。

验证脚本在受限 PATH 和隔离用户目录中运行，覆盖内置运行时、中文及空格路径、端口冲突、重复启动、离线示例、停止后重启、打包排除项与 SHA256，结果写入 `output/portable-verification.json`。它在当前 Windows 主机上模拟受限环境，不等同于全新 Windows 虚拟机验证。

### 上传到 GitHub Releases

1. 完成测试、构建与便携包验证，确认待发布的源码版本包含对应文档和截图。
2. 打开 [仓库 Releases](https://github.com/xvvic/ai-compliance-review/releases)，点击 **Draft a new release**，选择对应源码提交并创建版本标签，填写版本号和更新说明。
3. 在附件区域上传同次构建生成的 ZIP 和 SHA256 文件。保留上述固定文件名，README 按该名称指导用户下载。
4. 检查附件上传完成后发布版本。常规面向用户的版本应作为正式发布；预发布版本应在说明中标明用途。
5. 从 GitHub 页面重新下载 ZIP，比较校验值：

```powershell
Get-FileHash "$env:USERPROFILE\Downloads\AI-Compliance-Workbench-Windows-x64.zip" -Algorithm SHA256
```

6. 将下载结果与同次发布的 `.sha256` 内容比较。在新的目录中“全部解压”，双击“启动应用.vbs”，确认浏览器打开、示例报告可读、设置界面可操作，再双击“停止应用.vbs”并验证再次打开。尽可能在未安装开发依赖的 Windows 电脑上复核。
7. 确认未登录 GitHub 的读者也能打开发布页并下载正确附件。只有这一步完成后，README 的下载流程才对普通读者完整可用。

尚未上传便携包时，README 会提示等待发布；仓库中的源码压缩包不能替代便携包。

## 结构与接口

| 模块 | 职责 |
| --- | --- |
| `frontend/` | React、TypeScript、Ant Design 工作台 |
| `server.py`、`workbench/` | 文件解析、配置、单任务审查、SSE、报告与人工复核 |
| `launcher.py` | 本机进程管理、端口选择、浏览器启动 |
| `claude-code-plugin/ai-startup-compliance-review/` | 审查技能、规则与语料 |
| `scripts/` | 依赖锁定、示例资源准备、便携包构建与验证 |

`POST /review/stream` 接受 `document_text`，保留 `todos`、`tool_start`、`final`、`report_json` 成功事件，并提供 `started`、`error`、`done` 及审查 ID。调用方以 `done.status` 判断成功、失败或取消。

其他接口：`/api/health`、`/api/session`、`/api/config`、`/api/config/test`、`/api/documents/parse`、`/api/review/current`、`/api/review/{id}/events`、`/api/review/{id}/cancel`、`/api/review/{id}/decisions`、`/api/example`。写请求需携带 `/api/session` 返回的 `x-session-token`，仅接受同源本机请求。具体请求字段和返回类型以 `server.py` 与 `frontend/src/api.ts` 为准。
